# Evidence checklist

Keep individual records even when code is shared. Mark items complete only after actually performing them. Save screenshots with descriptive filenames and captions; omit credentials and personal account details.

## Required development work

- [ ] Record environment installation/setup, versions, and any introductory tutorials.
- [ ] Cite the existing sample and preserve its original starting point in Git.
- [ ] Build and run that sample on a physical device; demonstrate user input.
- [ ] Capture the running app and identify the device used.
- [ ] Commit code, write run instructions, and track tasks/bugs.
- [ ] Modify, build, test, deploy, and commit a partner's code.
- [ ] Fetch a partner's change to your code, rebuild, and deploy it on your device.
- [ ] Record coordination and debugging with partners.
- [ ] Deploy a backend web service and keep its code in revision control.
- [ ] Demonstrate app data sent/stored/retrieved through a REST API.
- [ ] Record the backend URL and a successful request/response without secrets.

## Individual submission

- [ ] Name, app description, reasons for choosing it, and learning objectives.
- [ ] Annotated references in approximate order of use, including sample code.
- [ ] Substantive AI/tool assistance: prompts, uses, checks, and lessons.
- [ ] Captioned screenshots/video links demonstrating features and tools.
- [ ] Repository URL, access arrangements, backend URL, and download/run instructions.
- [ ] Git history and links showing your contributions and exchanges.
- [ ] Narrative of planning, communication, debugging, and what you would change next time.
- [ ] Optional features documented if attempted; unsuccessful attempts described honestly.
